# Architecture and performance review, 2026-10-31

A whole-addon review (core, transport, shared Box helpers, every node group)
with the fixes that came out of it. Items marked **open** were confirmed but
not changed; they are listed so the next pass can pick them up.

## Transport: "late" bundles

scsynth logs `late <seconds>` for a timetagged bundle whose instant is already
behind the buffer it is computing. Its clock runs ahead of the wall clock by
the hardware buffer plus the device's output latency, so a stamp only a few
milliseconds ahead is late on most devices. Two sources produced them
constantly (STEAMING_STONES, for instance): the Box synth start-up helper
(`audio/scSynthStartup.h`) resumed every new voice / LFO / envelope synth with
a bundle stamped 10 ms ahead, and several nodes stamp "now" (the frame's
transport time, a timeline correction).

- `scStartConfiguredSynth` now configures first and creates running: the
  stored `set()` / `mapan()` calls ride on `/s_new` as creation arguments
  (scalars, arrays, bus mappings). Nothing is timed any more. It must send
  the `/s_new` as a bundle (`createAndRun`): during a graph rebuild the server
  latency stamps a lone message 200 ms ahead while a bundle runs on arrival,
  so a lone `/s_new` arrived after the Box's own routing resends ("Node not
  found"; PolyComb lost levels, insert routing and the resonator after a
  preset load or an encapsulation).
  `ofxSCNode::ensureNodeID()` gives the id before creation; a
  `resendStoredArgs()` before `/s_new` is a no-op (`isCreationRequested()`).
- `ofxSCServer::setMinimumLeadSeconds()`: a timetagged send closer than the
  lead goes out untimed (scsynth executes a late bundle on arrival anyway, so
  the audible result is identical, without the log). serverManager sets it to
  twice the buffer plus 5 ms, widens it when scStart sees three `late` lines
  within 5 s (capped at 50 ms), and eases it back after 30 quiet seconds.
- scsynth add actions: 0 head, 1 tail, **2 = before**, **3 = after**, 4 replace
  (`ofxSCNode::addBefore` is `create(2, …)`). One audit misread this; the
  code is right.

## Transport: ofxSuperCollider

- The OSC receive thread is owned and joined: `stop()` wakes the blocked
  `select()` with `AsynchronousBreak()` and joins before the socket goes (the
  ASan use-after-free on a destroyed server).
- Allocation generations: `ofxSCBus` / `ofxSCBuffer` remember the server's
  allocation generation; `free()` after a reboot gives nothing back (the range
  belongs to whoever got it next). Before, a stale free poisoned the fresh
  allocator and two buses shared a range (Global Pitch's block among them).
- A boot that never completed is forgotten (`resetBootState()` on kill /
  restart), and a relaunched scsynth is recognised by its state (a pristine
  status long after `/g_new`); the init `/sync` is re-sent after 20 s. Do not
  judge the server by missing status replies: while it installs the SynthDef
  tree its audio thread blocks and replies pause for seconds.
- `/b_info` for a freed or rebooted buffer no longer dereferences null.
- A packet over 65507 bytes is logged (it never arrives).

## Core and nodes

- `getLastSynthID` means the **head** of a node's chain (what an upstream
  node is placed before). GraphicEQ returned its FFT analyzer and DynGen its
  last voice: after any rebuild the upstream synth landed inside the chain and
  the node read silence.
- Replacing a synth on a channel change: swap the wrapper, send everything
  (queued as creation arguments), then `/s_new` with action 4. VUMeter,
  FastEnvelopeFollower, GraphicEQ and MixerPro's `setChannelCount` created
  first and ran on `in=0 / out=0` (the hardware buses) until `/n_go`.
- Generic SynthDef nodes (`scSynthdef`, `scOldSynthdef`): several inputs from
  one multi-output source (a sequencer's Gate and Pitch) each take their own
  port's bus; `getOutputBusIndex` returns -1 for unknown, never 0.
- MixerPro's destructor tears down the master sections (they ran on for the
  session). PolyMixer's two `sleep_for` on every rebuild are gone.
- Convolution restarts its IR after a rebuild (the VelvetReverb fix ported);
  CustomBuffer's `oldNumBuffers` is initialised; the dead `scBlockDelay.h` is
  removed; Timeline Wave Track only unregisters itself when it is the
  registered provider.
- Analyzers (A2K, PitchTracker, BeatTracker, FFT, FFTHD, Spectrogram,
  Lissajous) subscribe to `graphComputed` from setup, not only after the
  Server dropdown changes.
- The controller's config loading tolerates missing keys.

## Boxes: crashes and wrong sound

- GrainBox: removing an engine erased one of five morph policies registered
  for it (the rest dereferenced the freed engine on Store / recall).
- ChordBox: "+ Step", Duplicate, Remove, "+ Output", Steps and chord import
  rebuild the control registry at once and stop the frame's drawing loop
  (the controls referenced the vectors' old storage).
- SlicerBox: a preset with the same file but another marker count rebuilt
  nothing, so 64-wide control arrays reached a 16-slice player.
- EchoBox: a channel change left the route caches, and the new mix / reverb
  synths without `wet` / `in` / `out`.
- ArpeggiatorBox: a chunk's clear and data land in one bundle (a note could
  vanish between two packets); seeds switch instead of gliding through
  unrelated patterns; no status round trip in Transport mode.
- ChordBox: a step's first tick is the first tick at or after its start.
- EuclideanBox: a replaced player still awaiting `/n_go` is freed by id.
- MetroBox: Evolving mutations follow Seed > 0.
- SpectralFilterBox: Wrap recomputes the mask.
- Wavetable: a synth whose `/s_new` is in flight is replaced, not orphaned.
- PhysicalBox: drag state per instance. PulsarBox: Gate starts closed.
- AnalogBox: the Voices listener no longer rebuilds during a preset load.

## Boxes: per-frame OSC and CPU

- `scModulation::setBpm` returns when the tempo stands (GrainBox called it
  every frame; a tempo lane made every Box resend its LFO rates per frame).
  `updatePhases` sends only moved phases; parameter targets read the server at
  30 Hz; LFO output pins notify only on change; the Random salt is hashed
  once per control.
- `scSnapshots`: one library scan per folder per second for all instances;
  directories created once; a factory literal written as an integer glides.
- PolyComb: every part, the amp, the amp envelope and the spreader send
  through cached batches (a glide frame resent ~120 messages per server);
  the Pitch & Harmony tab no longer scans the scale library per frame.
- AdditiveBox: a note recomputes its own voice, not all of them.
- RhythmBox: a cabled or automated track control sends only what it touched
  (the whole slot, every track, every frame before); the per-track scalars and
  typed config are cached; proxy parameters are written only when they change;
  the slice zoom buttons no longer carry Solo's menu.
- GrainBox: a morph frame resends an engine only when its voice count
  changed; Position / Duration / Chance no longer rewrite the Amp Envelope
  block; a preset recall keeps the same sample's buffers; graph logging at
  verbose.
- SampleBox: a send iterates the pad's own controls (indexed) instead of
  every pad's; DrumKitBox iterates the specs of its destination.
- Aliasing / SteamPipe / Physical: an effect edit sends the stages, not the
  voice bank.
- DataBox playheads and Bufferscope poll only for an open window / at 30 Hz.

## GUI

- PolyComb: 5 tabs (Filters + Resonator; Envelopes, LFOs and Routing as
  Modulation; Panning with Effects). FMBox: 5 tabs (Operators with their
  envelopes; Matrix with the DX7 globals; Modulation; Effects).
- DrumKitBox opens its window by `getWindowId()` (MacroMixer sources).
- ArpeggiatorBox's Pulse Steps editor has the right-click menu.

## Open

- AnalogBox: toggling Drone changes the voice pool size (`allocating()`),
  so a Drone change or a morph crossing it rebuilds the whole voice graph.
  Needs the allocator to hold the pool while droning (or the extra voices
  muted), not a pool-size change.
- scVST: `ofSleepMillis` on the main thread in free / create / preset paths;
  FXP temp file deleted before the last instance read it; `removeParameterFromGUI`
  name heuristics.
- FM7 / FM7Drone ignore N Chan; Pink Trombone goes silent on N Chan.
- AdditiveBox has a sound control named "Morph", the snapshot system's own
  parameter name: it cannot be published or snapshotted under that name
  (renaming needs a preset migration).
- GrainBox 7 tabs, SteamPipe / Wavetable 6, RhythmBox 12 per-track tabs,
  SlicerBox 7; Arp / ChordBox / Pulsar / Wavetable / AdditiveBox ignore UI zoom.
- Spectrogram runs its FBO scroll pass per instance per frame whatever is
  visible; PolyMixer meters poll and notify per frame; VelvetReverb uploads
  its whole IR on every parameter tick.
- Duplication to extract into `shared/`: a Box control registry
  (publish / typed value / timeline / MIDI glue, four dialects today), the FX
  chain (stage structs, tails, routing, Effects tab), panning, per-server voice
  graph lifecycle, the onset-buffer player and anchor sender of the
  sequencers, the pad-kit skeleton (SampleBox / DrumKitBox), and an analyzer
  base for the plain-model analysis nodes.
